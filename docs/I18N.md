# Languages

The window (desktop app and browser /ui/, one set of files) shows its words in one of the six languages of the
United Nations or German, chosen under **Options → Language**: English, العربية (Arabic, right to left), 中文（简体）
(Simplified Chinese), Français, Русский, Español, Deutsch. Each is listed in its own script. English is the default.
The choice is the window's own, kept in localStorage like its look (docs/THEMES.md): the desktop app and each
browser choose for themselves, and app windows (appwindow.html) follow the window that chose. A new choice
applies at once, with no reload.

## How it works

The window is written in English, and the tabs stay plain English: English is the source of truth.
`crates/arcade-desktop/dist/i18n.js` loads first. For another language it loads that language's catalog
(`dist/locales/<code>.js`), then translates every text as it appears, whichever tab put it there (a
MutationObserver, which also watches a theme's frame). A text without a translation shows in English, so a new
screen never breaks a language, it only waits for its words. Every change remembers the English it replaced, so
switching back to English puts back exactly what the tabs wrote.

- **Plain text**: a text node's text, whitespace folded, is the key: `"Create a new wallet"`.
- **Text with values in it**: a JS template's `${...}` becomes `{0}`, `{1}`, … in order:
  `"{0} blocks behind"`. At run time the shown text is matched against it, and a value that is itself a known
  text is translated too. A pattern with few words of its own (`"{0} of {1}{2}"`) is used only where a value is
  a number or a known text, so it can't catch an unrelated sentence.
- **Sentences with markup**: elements holding only text are numbered, so a translator can move them:
  `"Use <0>Restore</0> on Home"` → `"Utilisez <0>Restaurer</0> dans Accueil"`. The window's own elements (ids,
  handlers) are put back where the translation puts them.
- `title`, `placeholder`, `aria-label`, `alt`, button values, `alert`/`confirm`/`prompt` are translated too.
- Never translated: `<code>`, `<pre>`, `<kbd>`, `<textarea>` contents, anything with `translate="no"` or class
  `notranslate`, addresses, hashes, @names, links.
- **Right to left**: Arabic sets `dir="rtl"` on the page. Flex and grid rows mirror by themselves; the rules
  written for left to right are mirrored at the end of style.css. Code, addresses and amounts stay left to right.

## For code

- Write plain English as before. Prefer one template over strings joined with `+`: `` `${n} blocks behind` `` is
  one text a translator can order; `n + " blocks " + "behind"` is fragments.
- Never decide on a shown label (`el.textContent === "Resume"`): keep the state in a data attribute
  (chains.js does this for Pause/Resume).
- Text that must stay as it is (a name, a command): `translate="no"`.
- `I18N.t("English")` gives the translation where code needs the string itself; `I18N.lang` is the shown
  language; `I18N.use(code)` switches; the window gets an `arcade:lang` event after a switch.

## Adding or fixing a string

```
scripts/i18n.py extract        # every English text in the window -> crates/arcade-desktop/i18n/en.json (key -> where it is)
scripts/i18n.py status         # per language: translated, missing, no longer used, placeholder/markup mismatches
scripts/i18n.py build          # crates/arcade-desktop/i18n/<code>.json -> dist/locales/<code>.js (what the window loads)
```

1. **Fix a translation**: edit `crates/arcade-desktop/i18n/<code>.json` (`{ "English": "translation", ... }`),
   then run `build`. Never edit `dist/locales/*.js` by hand: it is generated.
2. **A new English text** (a new screen, a changed sentence): run `extract`, then `status` lists it as missing in
   every language; add its translations to each JSON and run `build`. Until then it shows in English.
3. **A text the extractor can't see** (it comes from the service, or is built from pieces at run time): set
   `localStorage["arcade.i18n.collect"] = "1"`, use the window in that language, run `I18N.dump()` in its
   console, add the texts you want to `crates/arcade-desktop/i18n/runtime.json` (`extract` keeps them), and
   translate them as in 2.

Keep every `{n}` (a plural-"s" placeholder may be dropped, never added) and every `<n>`, `</n>`, `<n/>` (any
order); `build` leaves out a translation that lost one. Keep product terms as they are: ARCADE, arcade, Ord,
PSBT, coin names and tickers, @tags.

**A new language**: add it to `LANGS` in `i18n.js` (code → its own name; to `RTL` too if it is written right to
left), add `crates/arcade-desktop/i18n/<code>.json`, run `build`.

Warnings about keys, words and sending coins carry safety: translate them exactly, never soften them.
The catalogs are careful translations, not yet read by native speakers: corrections are welcome.
